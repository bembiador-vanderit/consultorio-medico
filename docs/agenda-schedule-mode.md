# Modalidad de agenda por médico y centro

Hasta 0053, cada par médico–centro tiene un modo habitual (`timed` o `queue`) y una excepción opcional por fecha; una jornada no admite ambos modos. La migración 0054 agrega `allowed_timed`, `allowed_queue` y `default_mode` a la configuración habitual y sus excepciones. Convierte el modo anterior a una sola modalidad permitida y **no** habilita ambas automáticamente. Tampoco cambia `schedule_mode`, hora ni orden de ninguna cita existente.

Después de activar 0054, la administración puede permitir Por hora, Por turno o ambas, y elegir una predeterminada entre las permitidas. La excepción de fecha reemplaza las tres opciones de la configuración habitual para ese día. La configuración sigue aislada por organización, centro y médico. La API `/api/v1/agenda-settings/{doctor_id}/{center_id}/{fecha}` conserva los campos legados de modo para compatibilidad y expone `base_policy`, `exception_policy` y `effective_policy`. Las escrituras requieren administración del tenant y permiso `centers:manage`.

El formulario consulta la política efectiva después de seleccionar centro, médico y fecha. En una cita nueva propone la modalidad predeterminada; si ambas están permitidas, permite elegir. Por hora requiere `appointment_time`; Por turno guarda la hora como `NULL`, asigna `daily_booking_order` y solo emite el turno al registrar llegada. El backend valida la modalidad pedida y exige una QueueLine activa para crear o mover una cita Por turno. No crea QueueLines automáticamente. La Agenda mantiene las secciones Por hora y Por turno y admite ambas en la misma fecha.

Al reducir las modalidades permitidas o cambiar la predeterminada, las citas existentes conservan su snapshot. Una cita Por turno ya registrada sigue operativa aun si después se desactiva esa modalidad o la QueueLine, conforme a sus propias reglas de llegada y atención. Las citas nuevas o reprogramadas deben cumplir la política vigente. Cambiar de modalidad al editar solo se permite para citas `scheduled` o `confirmed` sin turno emitido ni consulta clínica incompatible; nunca se convierte silenciosamente una cita atendida. La administración debe revisar las citas futuras antes de reducir modalidades: pueden coexistir snapshots anteriores con la nueva política.

**Despliegue:** el código puede correr frente a 0053, pero la selección multimodal queda deshabilitada hasta aplicar 0054. Esta microfase no aplica 0054 a la base oficial. El downgrade 0054→0053 se rechaza si alguna configuración permite ambas modalidades, para impedir pérdida silenciosa de información; se puede probar el ciclo completo sobre una base PostgreSQL temporal con políticas de una sola modalidad.
